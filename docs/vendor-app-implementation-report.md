# Nextou vendor app implementation report

The vendor workspace has been redesigned and its supporting contracts repaired in the local working tree. This report covers every active page, the components and APIs it uses, backend changes, removed features, verification results, and remaining acceptance work. The **screenshot-led third-pass section is the latest evidence**; earlier passes remain historical where superseded. The [redesign plan](vendor-app-redesign-plan.md), [baseline reference](vendor-app-complete-reference.md), and [coverage matrix](vendor-implementation-coverage.md) provide the inventory and implementation mapping. Browser rendering and builds do not establish that every retained action has passed acceptance.

Verified on 3 October 2026, Asia/Kolkata. The frontend uses Angular **21.2.25**, standalone components, Signals, and RxJS. The backend uses Django REST Framework, PostgreSQL, Channels/Redis, and RQ. The old Angular 19 description in repository guidance is historical.

The result includes the 21 originally required page destinations, plus a real transaction ledger and two password recovery destinations. Aliases and the shared feature-unavailable utility remain. No production orders, transfers, communications, or account credentials were changed. Changes have not been committed, pushed, or deployed. Existing admin, customer, shared-library, backend, and recommendation work was preserved.

## Design and navigation

The app follows the redesigned admin console's layout language while retaining vendor workflows: a dark sidebar, light work canvas, consistent panels, readable tables, labeled forms, and accessible dialogs. Vendor tokens are purple `#38268E`, hover `#23117C`, orange `#F97928`, canvas `#F6F7FA`, and text `#202334`. Nunito is the configured font. Headings are generally 24–28px and body text 15–16px, with smaller supporting labels. Material icons retain the established icon system.

`src/workspace.scss` defines vendor-only layout and control primitives. The shell has a 252px sidebar, grouped navigation, compact breadcrumbs, store state, profile menu, and a synchronized inbox preview. Duplicated global quick actions and repeated page titles were removed in the second pass. Long store names and usernames wrap within their containers. Tablet navigation uses an inert closed drawer with keyboard focus management; phone navigation adds a bottom bar. Dense lists use responsive cards or contained tables rather than extending the page horizontally.

Navigation groups are Operate, Catalog, Growth, Finance, and Account. Order History belongs in Operate; Payouts and Transactions belong in Finance. All 14 destinations remain available without duplicate links. Primary actions appear near the page heading; secondary actions remain with the affected record. Errors remain visible with recovery actions. Background refresh retains existing data instead of implying that an error means there are no records. Loading, empty, filtered-empty, forbidden, pending, stale, and failed states have distinct wording where applicable.

The broad compatibility `VendorApi` remains for established shared methods; new workspace contracts use the focused, typed `VendorWorkspaceApi` exported through the shared public API. This is an incremental boundary, not a complete removal of the old shared `ApiService`.

## API contracts and uses

All private calls carry the shared auth interceptor. Owner endpoints scope records to the authenticated vendor; operational endpoints require an approved vendor and appropriate security state. Public detail uses a dedicated whitelist. UUID path values are encoded by focused client methods. Paginated lists use `count`, `next`, `previous`, and `results`, with documented metadata for whole-scope summaries. An aggregate is not computed from the currently visible page.

The shared repository base moved to `helpers/repositories.py`; `vendors/data/base.py` reexports it for compatibility. This removes the product-repository/vendor-initialization import cycle without replacing historical migrations.

## Removed, consolidated and deferred features

Twelve source files belonging to four unrouted legacy pages were removed: `profile`, `stock-management`, `wallet`, and `product-form` (component/template/style for each). Their active capabilities now belong to Store Settings, Inventory, Transactions, and the separate product create/edit workflows. Import and build checks pass.

Old URLs remain usable: `/profile` → Store Settings, `/stock-management` and `/products/health` → Inventory, `/wallet` → Transactions, `/sales-report` → Analytics, `/payments` → Payouts, `/coupons` → Promotions, `/order/:id` and `/order/:id/tracking` → Order Detail. `/products/edit/:id` and `/store/settings` retain working guarded components and dirty protection.

Removed misleading semantics include unsupported shipping mappings, backorder/preorder controls, fake product readiness/suggestions, settlement records labeled as transactions, false bank-readiness failures, successful fallback location messages, unsupported review replies, and fictional support chat/import behavior. Native JavaScript alert/confirm/prompt flows have been replaced with application dialogs or persistent inline feedback. Named Signals/services containing `confirm` are application state, not native browser dialogs.

These additions still require product/backend/provider design before implementation:
